# Проверка прогнозов Stockan

Модель оценивает максимальное изменение **цены закрытия** за следующие 14 строк после объединения источников. Эти строки могут пропускать торговые сессии. Лимитная продажа зависит от внутридневной цены, а покупка должна исполниться до продажи. Для этих задач нужны разные метрики.

## Архив прогнозов

После каждого успешного анализа Actions сохраняет `latest_results.json` в артефакт `stockan-forecast`. В публичном репозитории такие артефакты доступны пользователям GitHub с доступом на чтение с учётом правил GitHub. Артефакты нужно скачивать до истечения срока хранения. Файл содержит прогнозы, дату и цену исходной свечи для каждого тикера, время формирования JSON и текущие метрики. Старые поля сохраняются для совместимости с Telegram-ботом.

Распакуйте архивы в отдельные подпапки `snapshots/`. Для свечей нужен CSV MOEX одного согласованного режима торгов с колонками `ticker,date,low,high,close`. Даты задаются в формате `YYYY-MM-DD`. Используйте цены в рублях в той же шкале, что и прогноз, одну свечу на тикер и дату. Периоды сплитов, приостановок торговли и пробелов в выгрузке нужно проверить перед интерпретацией результатов.

```sh
python tools/backtest_orders.py --snapshots snapshots --candles candles.csv \
  --trades trades.csv --fee-bps 5 --entry-sessions 1 --hold-sessions 10
```

Пять базисных пунктов в примере означают комиссию 0,05% на каждую сторону. Укажите фактическую комиссию.

Скрипт выбирает последний доступный снимок каждого московского дня и использует тикеры из обеих групп потенциала. Заявка действует с первой доступной свечи после дня сигнала. Лимит покупки на 0,5% ниже исходного закрытия, лимит продажи на 3% выше цены входа. Вход учитывается по лимиту при касании дневным минимумом. Выход по цели возможен с первой свечи после входа. При истечении срока позиция оценивается по закрытию последней свечи окна. Сроки измеряются свечами тикера.

CSV показывает исход каждой заявки. Незавершённые и пропущенные случаи учитываются отдельно. Доля достижения цели считается среди закрытых сделок, а средняя доходность учитывает комиссии на обе стороны. Для оценки потерь полезно просмотреть выходы по сроку на стрессовых датах и сравнить результаты для 5, 10 и 14 сессий.

Касание дневного максимума или минимума приближает исполнение. Данных об очереди заявок, спреде, проскальзывании и движении цены внутри свечи здесь нет. Сделки моделируются независимо, включая пересечения по одному тикеру. Для оценки портфеля нужны ограничения на капитал и размер позиции, правила повторного входа и учёт открытых позиций. Принудительный выход по сроку — сценарий теста для измерения убытка, который отличается от удержания просевших бумаг.

## Проверка модели по времени

Текущая CV использует обычные блоки KFold. Строки после тестового периода могут попасть в обучение, а целевые окна у соседних строк пересекаются. Синтетические индексы обучаются на всей истории. Поэтому текущий MAE в процентных пунктах — диагностическое число, а формула `100 - MAE` не даёт процент удачных сделок.

Для исторической оценки воспроизводите на каждую дату только данные, доступные на тот момент. В каждом проходе обучайте и синтетические индексы, и модели акций на прошлом. Включайте в обучение только цели, горизонт которых уже завершён к границе теста. Подбор гиперпараметров выполняйте во внутренних временных блоках. Проверяйте доступность капитализаций на дату сигнала при всех сравнениях.

Сравните действующую модель с простыми базовыми вариантами на одних датах, тикерах и торговых правилах. Для текущей цели базой может служить медиана роста за предыдущие завершённые окна. Для заявок — те же лимиты на всех доступных бумагах из того же списка без отбора по прогнозу. Измерьте MAE, среднее завышение прогноза и результаты по диапазонам прогнозируемого роста. Последний период и стрессовые окна проверяйте после фиксации правил.

- [Временные разбиения scikit-learn](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html)
- [Скользящее начало прогноза в Forecasting: Principles and Practice](https://otexts.com/fpp3/tscv.html)
- [Данные MOEX ISS](https://www.moex.com/a8531)

## Сравнение вариантов по кварталам

В ветке исследования запустите `Daily Stock Analysis` с параметром `walk_forward=true`. Этот режим строит датасет и сохраняет CSV с тремя прогнозами и фактической целью в артефакт `stockan-walk-forward`. Сводки `WALK_FORWARD` доступны в логе. Запись в Google Drive в этом режиме пропускается.

В каждом квартале с октября 2025 года модели обучаются один раз на его начало. Для обучения берутся только цели, все 14 будущих наблюдений которых уже прошли. Синтетические индексы переобучаются на данных до границы квартала, после чего восстанавливаются их значения и лаги. Из теста исключается цель, если в её окно попадает последняя доступная свеча. Отдельная сводка охватывает март–май 2026 года. Для этого режима курс USD загружается из [официального архива ЦБ](https://www.cbr.ru/development/SXML/) по дате вступления в силу. На дни без нового курса переносится последний действующий курс. Это закрывает дыры в рабочем кэше, которые видны при объединении рядов по дате.

Сравниваются медиана цели по завершённым обучающим окнам и две модели LightGBM с одинаковыми фиксированными параметрами. У одной веса одинаковы, у другой примеры с целевым ростом выше 12% удваиваются. Сохранённые параметры отдельных бумаг могли подбираться уже после тестовых дат, поэтому для сравнения они не загружаются.

MAE и среднее завышение выражены в процентных пунктах. Метрика топ-10 показывает, как часто следующая цена закрытия в пределах цели достигала заданного порога для бумаг с наибольшим прогнозом в тот же день. Исполнение заявки оценивается отдельным тестом лимитных ордеров. Текущий перечень бумаг и исторические капитализации используются ретроспективно. Для полноценной симуляции также нужны состав вселенной и исходные данные зафиксированные на каждую дату, включая время доступности дневных цен.
